# 밀성 손씨 교동파 족보

밀성 손씨 교동파의 구성원과 가족 관계를 조회하고 관리하는 웹사이트입니다. 구성원 목록·가계도·관계별 상세 이동과 함께, 관리자 권한에 따른 등록·수정·삭제·복원·동일인 병합을 제공합니다.

## 기술 구성

| 영역 | 구성 |
| --- | --- |
| 웹·API | Next.js 15.5.27, Pages Router |
| UI | React 18, CSS Modules |
| 데이터베이스 | PostgreSQL, 운영 DB는 Neon |
| 웹 호스팅 | Render |
| 가계도 | Google OrgChart |
| 이미지·PDF | html2canvas, jsPDF |
| 모바일 | PWA 및 Android/iOS WebView 소스 |

## 주요 기능

### 구성원 목록·상세·가계도

- 이름·출생 연도 범위 검색, 페이지 이동, 정렬 및 모바일 카드 목록.
- 구성원 상세에서 부모·형제·자녀의 상세와 가계도로 이동.
- **→ 가계도로 이동해서 보기** 버튼으로 해당 구성원의 위치를 중앙에 맞추고 강조.
- 가계도 확대·축소, 드래그 이동, 세로 휠 스크롤. 위·아래 끝에서는 페이지 스크롤로 연결.
- 가계도 PNG 및 여러 페이지 PDF 내보내기.
- 상세창의 구성원 ID는 관리 권한이 있는 계정에만 표시.

### 관리자 계정·권한

| 계정 | 조회 | 등록 | 수정·삭제 | 관리자 설정 |
| --- | --- | --- | --- | --- |
| 비로그인·조회 전용 | 가능 | 불가 | 불가 | 조회 전용 계정은 자신의 비밀번호 변경 가능 |
| 하위 관리자 | 가능 | 부여받은 권한에 따라 가능 | 부여받은 권한이 있고 **본인이 등록한 구성원만** 가능 | 자신의 작업 이력·비밀번호 |
| 상위 관리자 | 가능 | 가능 | 전체 구성원 관리 가능 | 계정·권한·승인·등록자 지정·전체 작업 이력 |

- 리스트 보기의 **관리자 회원가입 신청**으로 가입하고, 상위 관리자 승인 후 로그인.
- 상위 관리자는 가입 승인·거절·정지, 상위/하위 역할 및 등록·수정·삭제 권한 설정 가능.
- **관리자 계정 / 작업 이력 / 내 비밀번호** 화면을 분리하고 계정 목록은 카드로 표시.
- 상위 관리자 로그인 상태에서는 계정을 더블클릭하거나 **관리** 버튼을 눌러 바로 설정 진입. 설정 저장·비밀번호 초기화·계정 삭제에 별도 비밀번호 재입력 없음.
- 하위 관리자 직접 등록은 같은 등록란에서 새 계정의 아이디·이름과 상위 관리자 본인 비밀번호를 입력. 성공하면 임시 비밀번호를 한 번 표시하고 목록 갱신.
- 기존 구성원 등록자 지정도 본인 비밀번호 확인 후 처리.
- 임시 비밀번호로 생성된 계정은 첫 로그인 후 비밀번호를 변경해야 구성원 저장 가능.
- 마지막 활성 상위 관리자 계정의 삭제·정지·하위 역할 변경 제한.
- 계정 삭제는 로그인 차단 방식으로 처리하고 기존 족보와 작업 이력 보존.
- 로그인 유지 선택과 마지막 입력 아이디 기억. 비밀번호는 해시로 저장하고 서버 세션 사용.
- 비밀번호 확인은 실패한 요청만 횟수에 포함하고 성공하면 초기화. 반복 실패 시 15분 임시 차단.

### 작업자 표시·작업 이력

- 구성원 상세의 등록자·최종 수정자·등록일·수정일은 관리 권한 계정에만 표시.
- 조회 전용·비로그인 사용자의 상세·연관 인물 API 응답에서는 작업 메타데이터 제외.
- 등록자·수정자 이름이 없는 기존 데이터는 화면에서 **상위관리자**로 표시. 실제 DB 소유권은 유지하며 필요하면 상위 관리자가 등록자를 지정.
- 이후 등록·수정은 실제 작업한 관리자 계정과 시각을 기록.
- 운영 날짜 표시는 `YYYY-MM-DD`. DB에 저장된 시각은 유지.
- 등록·수정·삭제·복원·병합·계정 변경의 작업 이력과 변경 전후 값 기록.
- 이력은 날짜·작업자·작업·대상을 먼저 표시하고 펼치면 변경 전후 표 제공. 이름·작업·대상 검색 지원.
- 상위 관리자는 전체 이력, 관리 권한이 있는 하위 관리자는 자신의 이력 조회.

### 삭제·복원·중복 병합·관계 정합성

- 이름이 같은 구성원은 중복 후보로 안내하되 동명이인 등록 허용.
- 삭제자·삭제일·사유를 기록하는 논리 삭제와 삭제 목록·복원.
- 연결된 자녀·배우자가 있는 구성원의 일반 삭제 제한.
- 동일인 병합은 상위 관리자만 사용. 남길 ID·병합할 ID를 입력하고 값과 관계를 미리 확인한 뒤 사유를 적어 실행.
- 병합 시 자녀·배우자 관계 이전, 후손 세대 재계산 및 작업 이력 기록. 미리보기 이후 데이터 변경 여부를 확인하고 트랜잭션 처리.
- **병합은 일반 복원 버튼으로 되돌릴 수 없으므로** 같은 사람인지 부모·세대·생몰일 등을 확인.
- 자신·후손을 부모로 지정하는 순환 관계 차단.
- 부모 변경 시 후손 세대 변경을 미리 확인하고 재계산. 다른 등록자의 데이터까지 영향을 주는 변경은 상위 관리자 권한으로 제한.
- 배우자 ID와 어머니 관계를 연결해 배우자 이름 변경 시 관계 유지. 기존 미확정 관계 보존.
- 상위 관리자 메모 자동 저장, 저장 실패·초기화·이전 저장 요청과의 충돌 처리.

### 생몰일 입력

- 달력 선택 및 직접 입력: `YYYY`, `YYYY-MM-DD`, `YYYY.MM.DD`.
- 연도만 아는 날짜, 정확한 날짜, 미상을 구분. `0` 입력은 미상으로 해석하고 DB에는 `NULL` 저장.
- 출생·사망 순서와 실제 달력 날짜 검증. 생몰일은 달력 날짜로 처리해 시간대에 따른 변경 방지.
- 기존 1월 1일 데이터는 실제 날짜인지 연도만 아는 경우인지 자동 추정하지 않고 확인·보정 경로 제공.

### 반응형·모바일

- 헤더·로그인 영역 겹침 방지, 주 메뉴 줄바꿈, 좁은 화면의 검색 입력·상세창·계정 카드·병합 표 보완.
- 상세창 키보드 포커스와 Escape 닫기, 이동 버튼의 접근성 이름 제공.
- 휴대폰 홈 화면 추가 안내, PWA 아이콘·설치 및 오프라인 안내.
- 서비스 워커는 로그인·API·족보 데이터를 오프라인 캐시에 저장하지 않음. 조회·저장에는 인터넷 연결 필요.
- 기존 웹사이트를 여는 Android/iOS WebView 프로젝트 소스 제공. 패키지 빌드·서명·스토어 배포는 별도 준비 필요.

## 로컬 실행

Node.js 22에서 검증했습니다. `.env.example`을 참고해 `.env.local`에 개발용 `DATABASE_URL`을 설정합니다.

```sh
npm ci
npm run dev
```

접속 주소: `http://localhost:3000`.

빈 개발 DB 설치 시 마이그레이션 후, 관리자 계정이 없는 경우에만 초기 계정을 생성합니다.

```sh
npm run db:migrate
npm run db:bootstrap
```

초기 로그인 정보는 `.private/initial-admin.txt`에 저장됩니다. 이미 설치된 DB에서는 계정을 다시 생성하지 않습니다.

## 운영 DB 반영 상태

**2026-10-05 기준**, 사용자가 지정한 Neon 운영 DB에 다음 마이그레이션을 적용했습니다.

| 마이그레이션 | 내용 |
| --- | --- |
| `000-core-schema` | 기본 족보·배우자·메모·접속 로그 테이블 |
| `001-admin-system` | 관리자·세션·권한·작업 이력·등록자·수정자 |
| `002-member-safety` | 논리 삭제·병합·어머니 관계·생몰일 정확도 |
| `003-admin-lifecycle` | 관리자 계정 논리 삭제 |

적용 전후 백업을 만들고 **구성원 164명·배우자 92명의 기존 필드가 유지된 것**을 확인했습니다. 초기 상위 관리자도 생성했습니다. 이 수치는 반영 당시 기준이며 이후 운영 중 변경될 수 있습니다.

운영 초기 로그인 정보는 Git에서 제외한 `.private/production-initial-admin.txt`에 있습니다. 웹 배포 후 첫 로그인에서 비밀번호를 변경합니다. 로컬 관리자 계정과 운영 계정은 별개입니다.

운영 DB를 명시적으로 지정하는 작업은 비공개 연결 파일을 사용합니다.

```sh
node scripts/database.cjs inspect --url-file .private/production-database-url.txt
node scripts/database.cjs backup --url-file .private/production-database-url.txt
node scripts/database.cjs migrate --url-file .private/production-database-url.txt
```

`inspect`는 읽기 전용으로 대상과 설치 상태를 확인합니다. `migrate`는 먼저 백업하고 트랜잭션에서 구조를 변경합니다. 이미 적용된 운영 DB에 새로 반영할 내용이 없다면 다시 실행할 필요가 없습니다.

JSON 스냅샷은 **같은 스키마의 데이터 복구용**입니다. 전체 구조·뷰·역할까지 복구하는 PostgreSQL dump를 대신하지 않습니다. 백업·복구 및 정기 백업 설정은 [운영 문서](OPERATIONS.md)를 참고하세요.

## Git·Render 배포

GitHub에 변경 사항을 커밋·푸시하고 Render에서 **Deploy latest commit**을 실행합니다. 자동 배포가 설정된 서비스는 푸시 후 배포가 시작될 수 있습니다.

- Build Command: `npm ci && npm run build`
- Start Command: `npm start`
- `DATABASE_URL`: 배포할 Neon 운영 DB의 최신 연결 주소.
- `CRON_SECRET`: 운영 접속 확인·로그 정리 API 인증 값. 관련 GitHub Actions Secret과 일치하도록 설정.
- GitHub DB 백업 워크플로를 사용하는 경우 저장소의 `DATABASE_URL` Secret도 별도로 설정.

`.env.local`, `.private/`, `backups/`, `.next/`, `.verification/`, `node_modules/`는 Git에서 제외합니다. DB 비밀번호·초기 로그인 정보·백업은 공개하지 않습니다. 생성된 `.next` 파일의 기존 Git 추적도 정리했습니다.

배포 후 로그인, 관리자 계정 등록, 권한별 구성원 수정·삭제, 상세에서 가계도 이동 및 모바일 화면을 확인합니다. DB 마이그레이션 적용과 웹 코드 배포는 별도 작업입니다.

## 검증

```sh
npm test
npm run test:db
npm run lint
npm run verify:build
npm run test:http
```

- 회귀 테스트: 가계도 ID 선택·출력 이스케이프, 입력·날짜, 메모 저장 충돌, 권한·메타데이터 표시, 계정 등록 UI, 휠 스크롤, PDF·PWA.
- DB 통합 테스트: 실제 인증·권한 검사, 등록·수정·삭제·복원·관계 병합, 작업 이력, 마이그레이션·백업 데이터 복구. 임시 스키마에서 실행하고 테스트 데이터를 제거.
- 격리 운영 빌드 및 HTTP 테스트: 실제 서버 요청으로 로그인·저장·권한·응답 검증. 개발 서버의 `.next`를 덮어쓰지 않음.
- 실제 기기별 시각·터치 확인, PWA 설치 및 네이티브 패키지 빌드·스토어 배포는 별도 검증 필요.
